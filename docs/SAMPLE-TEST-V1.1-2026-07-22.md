# 影迹·EXIF V1.1 本地样片验证（2026-07-22）

## 范围

本轮使用本机 iCloud Drive 中的 Sony ARW、Nikon NEF、Pentax PEF、Apple DNG、Apple HEIC 和 TIFF 各一张。样片不复制进仓库，不记录作者、版权或精确 GPS 坐标。

验证目标：扩展名入口、文件格式显示、主要 EXIF、GPS、预览策略、中英文切换和移动宽度布局。V1.1 不进行 RAW 显影，也不把“能读取元数据”表述为“能预览所有编码”。

## 真实样片结果

| 格式 | 文件大小 | 元数据 / GPS | 预览结果 | 结论 |
| --- | ---: | --- | --- | --- |
| Apple DNG | 75.4 MB | 83 项；有 GPS | 没有尺寸足够的内嵌 JPEG，显示明确提示 | 通过 |
| Sony ARW | 88.3 MB | 浏览器中 91 项；有 GPS | 文件只提供 160×120 JPEG 缩略图，低于 320 px 门槛，不放大显示 | 通过 |
| Nikon NEF | 44.0 MB | Node.js 中 64 项；样片无 GPS | 解析器没有暴露可直接使用的 JPEG 缩略图 | 元数据支持通过；页面复测待完成 |
| Pentax PEF | 48.2 MB | Node.js 中 76 项；有 GPS | 解析器暴露的 JPEG 缩略图为 160×120，低于显示门槛 | 元数据支持通过；页面复测待完成 |
| Apple HEIC | 2.07 MB | 浏览器中 84 项；有 GPS | 当前本机测试浏览器不能原生预览，元数据仍正常显示 | 通过；仍需 Safari 等正式浏览器矩阵 |
| TIFF | 20.1 MB | 浏览器中 265 项；有 GPS | 浏览器原生失败后，本地后备模块成功生成 1800×1200 预览 | 通过 |

解析器在 Node.js 只读复核中成功读取全部六张样片。Node.js 没有浏览器的 `DOMParser`，因此 XMP 计数可能低于浏览器结果；这不代表元数据丢失。

NEF 和 PEF 的解析耗时分别约 10 毫秒和 18 毫秒，解析期间 RSS 增量约 48 MB 和 56 MB，均明显低于现有 ARW / DNG 样片的内存压力，因此继续沿用 RAW 150 MB 上限。

## 界面与布局

- 中文为默认界面；中文 / EN 切换后，页面标题、说明、按钮、状态、主要字段、GPS 和地图按钮同步变化。
- 刷新后保留上次语言；`?lang=en` 可直接进入英文界面。
- 图片已读入时切换语言不会重新读取文件，当前结果保持不变。
- 375×844 测试视口没有横向溢出；格式说明和地图按钮自动改为单列。
- 页面运行日志没有应用错误；GoatCounter 在 localhost 主动不计数的警告属于预期行为。

## 自动检查

`pnpm run check`：18 项测试中 12 项通过、0 项失败、6 项跳过。跳过项依赖未纳入仓库的旧版 JPEG 私人样片。新增测试覆盖：

- 无压缩 8-bit RGB TIFF 后备解码；
- 对不支持的 TIFF 压缩方式明确拒绝预览；
- V1.1 本地资源、RAW 上限、扩展名和英文文案结构。

## 尚未完成

本轮只完成一个本机浏览器环境的页面测试。发布审批前仍应按照 `docs/TESTING.md` 完成 macOS Safari / Chrome / Edge / Firefox、Windows Chrome / Edge / Firefox，以及 iPhone / iPad Safari 的正式矩阵，尤其核对 HEIC 原生预览、拖放、方向与内存表现。

加入 NEF / PEF 后再次启动 localhost 页面测试时，本机服务器的权限审批通道在进程启动前中断。因此这两张新增样片本轮完成了解析器、扩展名、格式命名、文件上限和静态结构验证，但尚未声称完成真实浏览器页面复测。
